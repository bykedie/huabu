# Decisions

- Use the reference repository as a visual and interaction benchmark, not as a source-copy target.
- Preserve the current commercial backend and data contracts while changing presentation.
- Use isolated CSS override files for this parallel phase so workers cannot collide in `src/styles.css`.
- Main thread owns integration and acceptance; workers own bounded implementation only.
- Worker progress is persisted in repository status files approximately every two minutes.
- Do not expose or repeat relay secrets.
- Keep frontend on port `5182` and API on port `3102`; do not use ports `3000` or `5174`.
- Use `PROJECT_MEMORY.md` as the durable index of user-confirmed goals, terminology, preferences, and unresolved historical conflicts. The user's latest explicit request overrides it, and secrets must never be recorded there.
- The 2026-08-01 image decision supersedes only the old fixed-endpoint clause: the server controls `AI_IMAGE_BASE_URL` (default `https://www.bkbk.baby/v1`), while each user's image API key remains encrypted and isolated and image requests remain free of site-point charges. Keep text and video relay behavior unchanged.
- When an idea has been accepted for execution, create a recoverable goal before implementation. The main thread acts as commander, delegates independent work to bounded collaboration threads or subagents, and owns final integration and acceptance.
- Keep only the current commander/main thread pinned. Collaboration and subagent threads remain unpinned. The user permits up to 10 concurrent workers for genuinely independent tasks, subject to the runtime's smaller slot limit; do not create workers just to fill capacity. Use `gpt-5.6-sol` with `Ultra` reasoning unless explicitly overridden.
- Keep the old `app_settings.ai_image_*` columns only as inert schema-compatibility fields for existing databases. Runtime image calls, public configuration, and administrator routes must not read or expose them.
- A user-entered image key may exist briefly in a password input's component state and request body, but it must be cleared after the request and must never enter localStorage, canvas documents, notices, logs, screenshots, API responses, or administrator state.
- Video result downloads are restricted to the relay origin and exact origins listed in `AI_VIDEO_MEDIA_ORIGINS`. Every redirect hop is handled manually, limited to five, and revalidated for origin and unsafe DNS/IP results. The relay authorization header is sent only to the relay origin. DNS validation still has a residual resolution-to-connect rebinding TOCTOU window, which remains a documented risk.
- An asynchronous video result that exceeds the user's media quota (`413`) is terminal: mark the generation failed and refund its reservation exactly once. Result-download `502/504` failures remain pending because a later poll can recover.
- `JWT_SECRET` is part of the encrypted database's recovery identity. Backups and restores must retain the matching value; `server/check-db.js` must reject databases whose text relay, video relay, or user image ciphertext cannot be decrypted by the current secret.
- Production backups must use a unique absolute directory outside the repository. Never place a full database backup in the worktree or Docker build context, and preserve the matching `JWT_SECRET` through a separate controlled secret-management process.
- The supported one-command production path is `deploy/install.sh` on Ubuntu/Debian with systemd. It preserves an existing `.env` and Compose data volume, rejects dirty or divergent deployment repositories, accepts only a fast-forward branch update, and runs the existing validated database backup before updating a running deployment. First-run secrets are generated locally on the server and are never printed by the installer.
- The default deployment path intentionally publishes `0.0.0.0:3102` over HTTP so a fresh server is reachable by public IP without a domain. The installer accepts only `0.0.0.0` or `127.0.0.1` binds and ports 1-65535, warns that HTTP is not encrypted, and installs `/usr/local/bin/h` only when an existing path is absent or already points to this project. Domain/Nginx/Certbot setup is optional and restores the previous Nginx site on validation or certificate failure.
- `deploy/manage.sh` is the operational control plane: it must not source `.env`, must preserve unrelated lines, must reject newline values, must use hidden input for relay keys, and must never print stored secrets. Its update path verifies repository origin, branch, clean state and fast-forward ancestry, then backs up before merging.
- Public host port changes require backup and restore health checks to read `PUBLIC_PORT` from `.env`; container port remains fixed at 3102.
- Deployment panel decision (2026-07-31): default PUBLIC_BIND=0.0.0.0 and configurable PUBLIC_PORT (default 3102) publish the fixed container port 3102; no domain is required for first launch. Nginx/Certbot are optional and only installed for domain mode. The installer and h panel warn that public HTTP is unencrypted.
- The h command is installed as a protected /usr/local/bin/h symlink to deploy/manage.sh. It rejects dirty or divergent Git updates, backs up before fast-forwarding, hides secrets with read -r -s, preserves .env values without shell evaluation, and requires explicit restore confirmation.
- Deployment hardening decision (updated 2026-08-01): `public` and `both` bind `0.0.0.0`; `domain` and `private` bind `127.0.0.1`. Express trusts forwarded headers only from loopback sockets, supporting Nginx in `domain/both` without trusting public clients. Installer and `h safe_update` retain the existing backup and rollback rules.
- Relay maintenance decision (2026-07-31): `h` sends hidden keys to `server/manage-config.js` through NUL-delimited standard input; text/video keys are AES-256-GCM encrypted in SQLite. Managed tombstones distinguish a legacy `.env` key from explicit `CLEAR`, prevent cleared keys from reviving, reject URLs with embedded credentials, clear legacy environment keys and force-recreate the app container.
- Backup and restore decision (2026-07-31): backup roots are resolved before and after creation, must remain outside the repository, and `app.db`/WAL/SHM symbolic links are rejected. A validated backup is retained when service recovery fails.
- Private backup compatibility decision (2026-08-01): deployment backups and restore work directories remain `0700 root:root`. One-shot database validation, migration and restore containers explicitly run as UID/GID `0:0` so they can traverse those private bind mounts; restored database files are then returned to the application runtime owner's UID/GID before the service starts. Do not fix this class of failure by making backup directories group- or world-readable.
- Operations localization decision (2026-08-01): the `h` menu, help, status, prompts, warnings, errors, results and `server/manage-config.js` maintenance output use Chinese. Keep the `status` subcommand and the `CLEAR`, `RESTORE` and `SHOW` safety tokens stable; do not translate internal routing values or change secret-handling behavior as part of localization.
- Relay-entry decision (updated 2026-08-01): `h` exposes independent text, image and video entries. Text/video retain encrypted administrator URL/key/model maintenance. The image entry updates `AI_IMAGE_BASE_URL` and `AI_IMAGE_MODELS`, but never accepts, displays or persists an administrator image key. A failed image configuration restores the previous `.env` and attempts to recover the previous healthy service.
- Access-mode decision (2026-08-01): first deployment defaults to public IP plus port and reports an automatically detected public IPv4. `MOYU_ACCESS_MODE` is one of `public`, `domain`, `both`, or `private`; `h` presents these as user-facing choices and preserves the selected mode on repeat installs. Disabling the domain entry removes only this project's Nginx enabled link and preserves its site/certificate files.
- Public-domain recovery decision (2026-08-01): treat DNS, application health and reverse-proxy/TLS as separate gates. `api.bkbk.baby` currently resolves through `bkbk.baby` to the wrong address, while the intended ECS also has a conflicting `Beaver` response/TLS failure. Do not claim repair after changing only DNS. Back up existing site state, obtain explicit approval for the traffic switch, then require HTTP redirect, hostname-valid TLS, HTTPS `/api/health` 200 and rendered-application acceptance before declaring completion.
- Domain automation decision (2026-08-01): domain mode binds the application to `127.0.0.1`, exposes only Nginx on 80/443, redirects HTTP to HTTPS and requests a Let's Encrypt certificate automatically. Certificate email is optional; when absent, Certbot uses `--register-unsafely-without-email`. Both the installer and `h` retain the prior environment/site and recover it on certificate or health failure. A future server must deploy from the GitHub branch through the same installer rather than depend on undocumented manual host state.
