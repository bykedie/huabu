# Decisions

- Use the reference repository as a visual and interaction benchmark, not as a source-copy target.
- Preserve the current commercial backend and data contracts while changing presentation.
- Use isolated CSS override files for this parallel phase so workers cannot collide in `src/styles.css`.
- Main thread owns integration and acceptance; workers own bounded implementation only.
- Worker progress is persisted in repository status files approximately every two minutes.
- Do not expose or repeat relay secrets.
- Keep frontend on port `5182` and API on port `3102`; do not use ports `3000` or `5174`.
- Use `PROJECT_MEMORY.md` as the durable index of user-confirmed goals, terminology, preferences, and unresolved historical conflicts. The user's latest explicit request overrides it, and secrets must never be recorded there.
- Historical image-only decision (superseded by the three-key decision below): the server controlled `AI_IMAGE_BASE_URL`, each user supplied an encrypted image key, and image requests remained free of site-point charges. Its instruction to keep shared text/video credential behavior unchanged is no longer current.
- When an idea has been accepted for execution, create a recoverable goal before implementation. The main thread acts as commander, delegates independent work to bounded collaboration threads or subagents, and owns final integration and acceptance.
- Goal-mode takeover decision (2026-08-02): Codex goal mode is the user's default execution preference for non-trivial project work. A request to read the handoff or take over the project explicitly authorizes a read-only takeover-audit goal. New sessions recover from repository documents, actual Git/code/tests/services, and must not read, fork, or restore historical thread IDs unless the user explicitly requests thread management.
- Continuous handoff checkpoint decision (2026-08-02): every goal must write and synchronize a final on-disk checkpoint before it is marked or reported complete. Before continuing into work or a next phase that may exceed the current context, write a mid-goal checkpoint first and keep the goal active. The canonical coordination checkpoint and synchronized goal/plan/status summaries must record the current goal, completed work, unfinished work, latest verification, modified files, exact next action, and concrete secret-free recovery commands so a replacement session does not depend on chat history.
- Keep only the current commander/main thread pinned. Collaboration and subagent threads remain unpinned. The user currently permits at most 3 concurrent workers for genuinely independent tasks, subject to the runtime's smaller slot limit; never exceed this cap unless the user explicitly changes it again, and do not create workers just to fill capacity. Use `gpt-5.6-sol` with `Ultra` reasoning unless explicitly overridden.
- Keep the old `app_settings.ai_image_*` columns only as inert schema-compatibility fields for existing databases. Runtime image calls, public configuration, and administrator routes must not read or expose them.
- A user-entered text, image, or video key may exist briefly in its password input's component state and request body, but it must be cleared after the request and must never enter localStorage, canvas documents, notices, logs, screenshots, API responses or administrator state.
- Video result downloads are restricted to the relay origin and exact origins listed in `AI_VIDEO_MEDIA_ORIGINS`. Every redirect hop is handled manually, limited to five, and revalidated for origin and unsafe DNS/IP results. The relay authorization header is sent only to the relay origin. DNS validation still has a residual resolution-to-connect rebinding TOCTOU window, which remains a documented risk.
- An asynchronous video result that exceeds the user's media quota (`413`) is terminal: mark the generation failed and refund its reservation exactly once. Result-download `502/504` failures remain pending because a later poll can recover.
- `JWT_SECRET` is part of the encrypted database's recovery identity. Backups and restores must retain the matching value; strict `server/check-db.js` must reject databases whose user text/image/video ciphertext or encrypted administrator password cannot be decrypted by the current secret. `--allow-legacy` remains available only for pre-migration backup validation.
- Production backups must use a unique absolute directory outside the repository. Never place a full database backup in the worktree or Docker build context, and preserve the matching `JWT_SECRET` through a separate controlled secret-management process.
- The supported one-command production path is `deploy/install.sh` on Ubuntu/Debian with systemd. It preserves an existing `.env` and Compose data volume, rejects dirty or divergent deployment repositories, accepts only a fast-forward branch update, and runs the existing validated database backup before updating a running deployment. First-run secrets are generated locally on the server and are never printed by the installer.
- The default deployment path intentionally publishes `0.0.0.0:3102` over HTTP so a fresh server is reachable by public IP without a domain. The installer accepts only `0.0.0.0` or `127.0.0.1` binds and ports 1-65535, warns that HTTP is not encrypted, and installs `/usr/local/bin/h` only when an existing path is absent or already points to this project. Domain/Nginx/Certbot setup is optional and restores the previous Nginx site on validation or certificate failure.
- `deploy/manage.sh` is the operational control plane: it must not source `.env`, must preserve unrelated lines, must reject newline values, and must never print stored secrets. It does not configure text/image/video relays; those addresses and models are managed only in web Operations. Its update path verifies repository origin, branch, clean state and fast-forward ancestry, then backs up before merging.
- Public host port changes require backup and restore health checks to read `PUBLIC_PORT` from `.env`; container port remains fixed at 3102.
- Deployment panel decision (2026-07-31): default PUBLIC_BIND=0.0.0.0 and configurable PUBLIC_PORT (default 3102) publish the fixed container port 3102; no domain is required for first launch. Nginx/Certbot are optional and only installed for domain mode. The installer and h panel warn that public HTTP is unencrypted.
- The `h` command is installed as a protected `/usr/local/bin/h` symlink to `deploy/manage.sh`. It rejects dirty or divergent Git updates, backs up before fast-forwarding, preserves `.env` values without shell evaluation, never prints secrets, and requires explicit restore confirmation. Historical relay/shared-key entries are removed; safe update remains item 5.
- Deployment hardening decision (updated 2026-08-01): `public` and `both` bind `0.0.0.0`; `domain` and `private` bind `127.0.0.1`. Express trusts forwarded headers only from loopback sockets, supporting Nginx in `domain/both` without trusting public clients. Installer and `h safe_update` retain the existing backup and rollback rules.
- Historical relay maintenance decision (superseded 2026-08-01): `h` once sent hidden shared text/video keys to `server/manage-config.js` and used managed tombstones for legacy `.env` migration. Current `h`, Compose and maintenance APIs do not accept or inject shared runtime keys; compatibility columns remain inert.
- Backup and restore decision (2026-07-31): backup roots are resolved before and after creation, must remain outside the repository, and `app.db`/WAL/SHM symbolic links are rejected. A validated backup is retained when service recovery fails.
- Private backup compatibility decision (2026-08-01): deployment backups and restore work directories remain `0700 root:root`. One-shot database validation, migration and restore containers explicitly run as UID/GID `0:0` so they can traverse those private bind mounts; restored database files are then returned to the application runtime owner's UID/GID before the service starts. Do not fix this class of failure by making backup directories group- or world-readable.
- Operations localization decision (2026-08-01): the `h` menu, help, status, prompts, warnings, errors, results and `server/manage-config.js` maintenance output use Chinese. Keep the `status` subcommand and the `CLEAR`, `RESTORE` and `SHOW` safety tokens stable; do not translate internal routing values or change secret-handling behavior as part of localization.
- Historical relay-entry decision (superseded 2026-08-02): `h` no longer exposes text, image, or video relay entries. Web Operations is the only normal surface for relay addresses, upstream discovery, and open-model selection.
- Access-mode decision (2026-08-01): first deployment defaults to public IP plus port and reports an automatically detected public IPv4. `MOYU_ACCESS_MODE` is one of `public`, `domain`, `both`, or `private`; `h` presents these as user-facing choices and preserves the selected mode on repeat installs. Disabling the domain entry removes only this project's Nginx enabled link and preserves its site/certificate files.
- Root credential-display decision (2026-08-01): at the user's explicit request, `h status` displays administrator email and password to the root terminal. Login still uses bcrypt; an additional AES-256-GCM ciphertext derived from `JWT_SECRET` is stored only for administrator passwords, updated on administrator registration/password change, never returned by application APIs, and validated during backup/restore. Pre-existing administrator passwords cannot be recovered from bcrypt and display only after the administrator changes the password once.
- Public-domain recovery decision (2026-08-01): treat DNS, application health and reverse-proxy/TLS as separate gates. `api.bkbk.baby` currently resolves through `bkbk.baby` to the wrong address, while the intended ECS also has a conflicting `Beaver` response/TLS failure. Do not claim repair after changing only DNS. Back up existing site state, obtain explicit approval for the traffic switch, then require HTTP redirect, hostname-valid TLS, HTTPS `/api/health` 200 and rendered-application acceptance before declaring completion.
- Domain automation decision (2026-08-01): domain mode binds the application to `127.0.0.1`, exposes only Nginx on 80/443, redirects HTTP to HTTPS and requests a Let's Encrypt certificate automatically. Certificate email is optional; when absent, Certbot uses `--register-unsafely-without-email`. Both the installer and `h` retain the prior environment/site and recover it on certificate or health failure. A future server must deploy from the GitHub branch through the same installer rather than depend on undocumented manual host state.
- User-owned three-key relay decision (updated 2026-08-02, current): runtime relay authentication comes from the authenticated user's own encrypted text, image, or video key. Account Security provides exactly those three key controls and does not reveal relay endpoints. Web Operations controls separate relay addresses and open models; administrator tests and model discovery use that administrator's saved corresponding user key. Legacy administrator key columns may remain only for additive schema compatibility, not as active runtime, Compose, `h`, or API credential sources.
- Relay secret-reflection decision (2026-08-01): upstream-controlled errors, content, nested usage, model identifiers, image results, video task IDs/result URLs/download failures and cached values must be rejected or redacted when they contain the current user's raw or URL-encoded key. They must not enter API responses, logs, audit rows, generation rows, ledger rows, cached results or persisted task/media fields.
- Relay-model selection decision (updated 2026-08-02): Operations can request the text, image, or video upstream `/models` list with the administrator's corresponding user key, normalize and deduplicate identifiers, replace the current candidates, and require an explicit new selection before saving. Agent chat and generation nodes use only the saved open lists; the server remains authoritative and rejects models outside them.
- Public-HTTP compatibility decision (2026-08-01): browser identifiers and core canvas actions must not rely on APIs limited to secure contexts. Use a single UUID helper that prefers `crypto.randomUUID`, falls back to `crypto.getRandomValues`, and retains a final non-cryptographic uniqueness fallback only for client-side UI/document identifiers. Final acceptance must include a genuinely non-secure HTTP origin because localhost can conceal this defect.
- Concurrency decision (updated 2026-08-02): one active worker remains the default. When the user explicitly approves concurrency, no more than 3 child workers/subthreads may be active at once unless the user later changes that cap.
- Web relay modernization decision (2026-08-02): fresh text/image model lists are empty; all three model kinds support upstream discovery in web Operations; text uses Responses first with 404/405-only Chat Completions fallback; `SITE_BILLING_ENABLED` defaults to `0`; billing/recharge UI is hidden; text/video create zero site-point reservations by default while the opt-in ledger path remains test-covered; image remains zero site points.
- Delivery-state decision (updated 2026-08-02): local implementation, GitHub delivery, and production deployment are distinct states. Product commit `90e091aab59bdbeaf8f3b8edcdc2e28bd06c8098`, handoff documentation commit `44dd2441a9df836277905fdf784aeda0ac725c32`, and the final checkpoint commit were normally pushed and remotely verified; the GitHub delivery is complete. Production remains `3f7b52d` until the user runs MobaXterm `h` item 5 and completes a new production acceptance.
- Canvas generation-context decision (2026-08-02): connected context remains typed through traversal. Only text and note nodes contribute visible prompt text; image nodes contribute at most four image references; video, AI and group fields, media URLs and `data:` payloads never enter visible prompts. The user's current prompt remains first, followed by connected textual context.
- Canvas node-interaction decision (2026-08-02): a ready image preview hides its URL editor, locked image resize uses `object-fit: contain`, and free resize may stretch with `object-fit: fill`. Text and note nodes expose a dedicated 36px drag surface; the AI node uses a 44px title/mode drag header and a `300x280` minimum so its bottom generation action remains reachable. Form controls remain editable. The top import action accepts either one draft JSON or an image group and rejects mixed selections.
- AI creation-card decision (2026-08-02): keep the existing text/image/video modes and stored document fields, but present them as a compact ordered card: title/mode drag header, elastic prompt, typed connected-context summary, fixed generation settings and a bottom action. Normalize older undersized AI nodes on draft/server load and use the normalized nodes as the undo baseline; do not add reference-only audio controls or copy the AGPL implementation.
- Screenshot-review decision (clarified 2026-08-02): inspect at most one user-provided original screenshot and invoke image viewing at most once per turn; never create or inspect derived crops, composites, enlargements or thumbnails. End the turn after that screenshot's analysis. This controls context growth and is not an authorization gate: a later continuation turn may inspect the next pending original screenshot automatically unless the user pauses or redirects the goal, with no required `看下一张` phrase.
- Image-toolbar geometry decision (2026-08-02): keep image quick tools inside React Flow's node-local coordinate system. Clamp the toolbar and settings panel to the active renderer, flip below the node when the top edge lacks space, keep wide tools in their own horizontal scroller, avoid the bottom canvas Dock while settings are open, and allow the settings panel to scroll in short viewports. Do not restore fixed application-edge positioning.
- AI interaction delivery decision (updated 2026-08-02): automated and browser acceptance passed, and feature commit `ca6ed672541b70c357edc5acd9cbbd84a1f43ddb` was pushed normally to `origin/codex/infinite-canvas`. GitHub delivery is complete; production deployment remains a separate user-directed action.
- AI usability decision (2026-08-02): newly entered relay keys use verify-then-save semantics; manual AI context edges persist independently of drag direction; generated output edges are excluded from context; missing administrator models produce explicit feedback; connection handles remain visible circular input/output markers. This contract was delivered in `7c774c1` with documentation closeout `3995f17`.
- AI runtime compatibility decision (2026-08-02): text relay calls explicitly request `stream: false` for both Responses and Chat Completions. Text-mode AI creation displays and sends at most four connected image references using protocol-specific multimodal blocks while keeping image data out of visible prompts. Canvas Assistant leaves the textarea DOM-owned during IME composition, synchronizes after composition, ignores composition or key code 229 Enter events, and submits exactly once outside composition without character-level deduplication. This repair was delivered as `90e091a` with handoff closeout `44dd244`; production remains undeployed.
- Asset persistence decision (2026-08-02): formal canvas documents and asset-library records live in server SQLite (`canvases` and `assets`), and persisted video media lives in `media`. Browser localStorage is limited to recoverable unsynced drafts, AI request idempotency keys, and UI preferences; it is not the formal asset library.
